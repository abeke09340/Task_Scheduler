# План реализации: Планер (MVP, базовый интерфейс)

> Исполнитель: Gemini. Источник правил: `SPEC.md`. Референсы дизайна: папка `design/` (5 скриншотов).
> Цель этапа: рабочее веб-приложение в браузере (`localhost:5173`) с 5 экранами, данными в `localStorage` и архитектурой, готовой к подключению Supabase.

---

## 0. Решения, которые фиксируем до старта

| Вопрос | Решение | Почему |
|---|---|---|
| Фреймворк | **React 19 + Vite + TypeScript** | Быстрый dev-сервер, просмотр в браузере, PWA |
| Стили | **Tailwind CSS v4** + CSS-переменные (токены) | Строгая сетка 8px, единые цвета |
| Роутинг | **react-router** v7 | 5 страниц с URL |
| Состояние | **zustand** + middleware `persist` (localStorage) | Минимум кода, легко заменить на Supabase |
| Даты | **date-fns** + локаль `ru` | Русские названия дней/месяцев |
| Иконки | **lucide-react** (stroke 1.75, size 18) | Тонкие линейные иконки, как на макетах |
| Шрифт | **Inter** (`@fontsource-variable/inter`) | По промпту |
| PWA | **vite-plugin-pwa** — в последней фазе | Установка на iPhone/Android/Mac |
| Бэкенд | **Нет.** Только слой `storage/` с интерфейсами | Подключение Supabase позже без переписывания UI |
| Валюта | **₸** | Как на макетах |
| Имя пользователя | **Абдували** (константа в настройках, не «Иван П.») | Макеты противоречат друг другу |

### Расхождения в макетах и как их решаем
1. **Меню в сайдбаре разное на каждом скрине.** Фиксируем 5 пунктов:
   `Обзор` (LayoutDashboard) → `Цели` (Target) → `Распорядок` (Clock) → `Календарь` (CalendarDays) → `Привычки` (Sprout).
   Пункт **«Задачи» в MVP не делаем**: задачи на сегодня = цели периода «День» (показываются на Обзоре).
2. **Заголовок «Calendar» на английском** — неверно. Везде только русский: «Календарь».
3. **Переключатель периодов целей:** в SPEC он внизу экрана, на макете вверху. Решение:
   **десктоп (≥ 768px)** — сегментированный контрол под заголовком (как на макете);
   **мобильный (< 768px)** — тот же контрол закреплён внизу экрана под большим пальцем (как в SPEC).
4. **Домашняя страница** на макете не в меню → это пункт «Обзор», маршрут `/`.

## 1. Дизайн-токены (обязательны, никаких «своих» цветов)

```css
/* src/styles/tokens.css */
--bg: #F7F6F3;          /* фон приложения и сайдбара */
--surface: #FFFFFF;     /* карточки */
--border: #E8E6E1;      /* hairline 1px */
--text: #1F1F1F;
--text-muted: #8A8A85;
--accent: #5B6CFF;      /* единственный акцент: кнопки, чекбокс, прогресс целей, «сейчас» */
--accent-soft: #ECEEFF;
--track: #ECEBE8;       /* фон прогресс-бара */
--pill: #EDECE8;        /* активный пункт сайдбара */

/* Пастели категорий: fill / text (тёмный вариант для текста и левой полосы) */
--sage:     #C9D6C3 / #4F6B47;   /* Здоровье, привычки */
--blue:     #C3D0DD / #435A73;   /* Работа / Карьера */
--apricot:  #F6D6B3 / #8A5A2B;   /* Личное, Учёба-блоки */
--lavender: #DCD1EC / #5E4B80;   /* Учёба / Разное */
--rose:     #EBC4C6 / #8A4148;   /* Финансы */
--sand:     #E9E1CF / #6E6247;   /* Хобби */
```

**Правила:** радиус карточек 12px, блоков в сетке 8px; отступы кратны 8 (8/16/24/32/48); тени запрещены (максимум `0 1px 0 rgba(0,0,0,.02)`); 3 размера шрифта: 32px/600 (заголовок страницы, большие числа), 15px/500 (основной), 13px/400 (вторичный). Анимации 150–200ms ease-out, только transform/opacity.

**Запрещено:** градиенты, glassmorphism, свечение, эмодзи в UI, иллюстрации, второй акцентный цвет, тяжёлые тени.

## 3. Модели данных (`src/types/models.ts`)

Сразу в форме таблиц будущей БД (Supabase/PostgreSQL): `id` (UUID), `userId`, `createdAt`, `updatedAt`.

```ts
type ID = string;
type ISODate = string;      // '2026-11-04'
type ISODateTime = string;  // '2026-11-04T15:00:00'

interface BaseEntity { id: ID; userId: ID; createdAt: ISODateTime; updatedAt: ISODateTime; }

type ColorKey = 'sage' | 'blue' | 'apricot' | 'lavender' | 'rose' | 'sand';
type Period = 'day' | 'week' | 'month' | 'year';
type Priority = 'low' | 'medium' | 'high';

interface Category extends BaseEntity { name: string; color: ColorKey; isDefault: boolean; order: number; }

interface SubGoal { id: ID; title: string; done: boolean; }

interface Goal extends BaseEntity {
  title: string;
  description?: string;
  categoryId: ID;
  period: Period;
  periodStart: ISODate;      // начало дня/недели(пн)/месяца/года, к которому относится цель
  priority: Priority;        // по умолчанию 'medium'
  deadline?: ISODateTime;
  subgoals: SubGoal[];
  completedAt?: ISODateTime; // отмечена вручную
}

interface ScheduleBlock extends BaseEntity {   // шаблон недели (повторяется)
  title: string;
  weekday: 1|2|3|4|5|6|7;    // 1 = Пн
  start: string;             // 'HH:mm'
  end: string;
  color: ColorKey;
}

interface Reminder extends BaseEntity {
  title: string;
  at: ISODateTime;
  color: ColorKey;           // Работа=blue, Финансы=rose, Личное=apricot, Здоровье=sage, Разное=lavender
  notify: boolean;
}

interface Habit extends BaseEntity { name: string; order: number; archived: boolean; }
interface HabitLog { habitId: ID; date: ISODate; }   // запись есть = выполнено
```

**Прогресс цели** (`lib/progress.ts`): если есть подцели → `done / total`; если нет → `completedAt ? 100 : 0`. Отметка чекбокса цели ставит все подцели в `done`. Прогресс периода = среднее по целям периода.

**Категории по умолчанию (6, `isDefault: true`):** Здоровье (sage), Финансы (rose), Учёба (lavender), Карьера (blue), Отношения (apricot), Хобби (sand). Пользовательские можно добавлять/редактировать/удалять; дефолтные можно переименовать, но не удалить.

### Слой хранения (`storage/`)
```ts
interface Repository<T> { list(): Promise<T[]>; upsert(item: T): Promise<void>; remove(id: ID): Promise<void>; }
```
Сторы zustand вызывают **только** репозитории. Методы асинхронные уже сейчас — чтобы замена `local.ts` на `supabase.ts` не трогала UI. Ключи localStorage с версией: `planner:v1:goals` и т.д. `userId = 'local'`.

## 4. Фазы работы

### Фаза 1 — Каркас проекта
- `npm create vite@latest . -- --template react-ts` в папке `Task Scheduler` (не удалять SPEC.md, PLAN.md, design/).
- Установить: `tailwindcss @tailwindcss/vite react-router zustand date-fns lucide-react @fontsource-variable/inter`.
- Подключить токены, Inter, `lang="ru"` в `index.html`, `<title>Планер</title>`.
- Удалить шаблонный контент Vite (логотипы, счётчик, App.css).

**Готово, когда:** `npm run dev` открывает пустую страницу на фоне `#F7F6F3` шрифтом Inter, без ошибок в консоли.

### Фаза 2 — Layout и UI-кит
- **Sidebar** (ширина 232px, фон `--bg`, правая hairline-граница): логотип «Планер» сверху; 5 пунктов; активный — серая «таблетка» `--pill`, радиус 8px; внизу аватар-иконка + «Абдували».
- **Мобильный (< 768px):** сайдбар скрыт → верхняя панель с кнопкой меню, сайдбар выезжает поверх (drawer) с затемнением; закрытие по клику вне/Esc/выбору пункта.
- **UI-компоненты:** `Button` (primary — индиго, ghost), `Card`, `Checkbox` (круглый, 20px; выполнено — заливка индиго + белая галочка), `ProgressBar` (6px, скругление, цвет через пропс), `Tag` (пастель + тёмный текст, 12px), `SegmentedControl`, `Modal` (центр на десктопе, bottom sheet на мобильном), `Input`, `Textarea`, `Select`, `EmptyState` (текст + кнопка, без картинок).

**Готово, когда:** переключение 5 маршрутов работает, активный пункт подсвечивается, на ширине 390px сайдбар открывается как drawer.

### Фаза 3 — Цели (главный экран, делать максимально качественно)
По макету `design/goals.jpg`:
- Заголовок «Цели» + кнопка «+ Новая цель» справа.
- `SegmentedControl`: День / Неделя / Месяц / Год (состояние в URL: `/goals?period=week`). По умолчанию «Неделя».
- Карточка «Прогресс недели / месяца / …» с большим процентом и баром.
- Список `GoalCard`: чекбокс, название, тег категории справа, бар + процент. Выполненные — зачёркнутое приглушённое название, уходят в конец списка. Сортировка: невыполненные по приоритету (высокий → низкий), затем по дедлайну.
- Индикатор приоритета: маленькая точка/флажок только для «Высокого» (не шуметь).
- Клик по карточке → разворачивается: описание, дедлайн («до 8 ноября»), список подцелей с чекбоксами, поле «+ Добавить шаг» (Enter добавляет).
- **Модалка цели** (создание/редактирование): Название*, Описание, Категория* (+ «Новая категория» прямо из выпадающего списка: название + выбор из 6 пастелей), Период*, Приоритет (Низкий/Средний/Высокий), Дедлайн, Подцели. Кнопки «Сохранить» / «Отмена», в режиме редактирования — «Удалить» (с подтверждением).
- Пустое состояние: «На эту неделю целей пока нет» + кнопка «Новая цель».
- Мобильный: `SegmentedControl` закреплён внизу экрана (safe-area-inset-bottom).

**Готово, когда:** можно создать, отредактировать, отметить, удалить цель и подцели; прогресс пересчитывается сразу; после перезагрузки страницы всё сохраняется.

### Фаза 4 — Обзор (`/`)
По макету `design/home.jpg`:
- Приветствие по времени суток: «Доброе утро» (5–12), «Добрый день» (12–17), «Добрый вечер» (17–23), «Доброй ночи» — + «, Абдували». Под ним дата: «Среда, 4 ноября».
- 3 карточки: «Цели недели» (% + индиго-бар), «Привычки сегодня» (X/Y + sage-бар), «Напоминаний сегодня» (число + blue-бар).
- «Сегодня»: цели периода «День» с чекбоксами (отметка работает прямо тут). Без зелёной заливки строки, как на макете — только зачёркивание.
- «Ближайшие напоминания»: 3 ближайших будущих на сегодня — время + цветная точка + название.
- Карточки кликабельны → ведут на соответствующий раздел.

### Фаза 5 — Привычки (`/habits`)
По макету `design/habits.jpg`:
- Заголовок, переключатель месяца «‹ Ноябрь 2026 ›», кнопка «+ Привычка».
- Карточка «Общий прогресс месяца» (% выполненных ячеек от прошедших дней).
- Сетка: колонка названий (sticky слева) | дни 1–N месяца (сегодня — индиго-кружок) | % + тонкий sage-бар.
- Ячейка 20px: выполнено — sage-заливка + белая галочка; пусто — серый контур; будущие дни — не кликабельны и бледнее.
- Клик по ячейке переключает `HabitLog`. Процент привычки считается от прошедших дней месяца, не от всех 30.
- Добавление/переименование/удаление привычки (клик по названию → меню).
- Мобильный: горизонтальный скролл сетки, колонка названий закреплена; автоскролл к сегодняшнему дню.

### Фаза 6 — Распорядок (`/schedule`)
По макету `design/schedule.jpg`:
- Заголовок «Распорядок», «‹ › Неделя 10–16 ноября», сегмент «Неделя / День».
- Сетка: колонки Пн–Вс с датами, сегодня — индиго-текст + точка; строки 07:00–22:00, высота часа 48px.
- Блоки позиционируются абсолютно: `top = (startMin − 420) / 60 × 48`, `height = длительность / 60 × 48 − 2`. Внутри: название и время мелким текстом (время скрывать, если блок < 40px).
- Блоки — недельный шаблон (одинаковые каждую неделю); стрелки меняют только даты в шапке.
- Клик по пустому месту → модалка «Новый блок» с предзаполненным днём и часом; клик по блоку → редактирование/удаление. Поля: Название, Дни недели (мультивыбор — создаёт блок на каждый день), Начало, Конец, Цвет.
- Режим «День» и мобильный: одна колонка текущего дня, свайп/стрелки для смены дня.

### Фаза 7 — Календарь (`/calendar`)
По макету `design/calendar.jpg`:
- Слева (~35%): мини-календарь «Ноябрь 2026», дни Пн–Вс, сегодня — заливка индиго, выбранный день — серый контур, под днями — до 3 цветных точек напоминаний.
- Справа (~65%): «Среда, 4 ноября» + кнопка «+ Напоминание»; легенда (Работа, Финансы, Личное, Здоровье, Разное); таймлайн 08:00–21:00.
- Линия «сейчас» (индиго, точка слева) — только для сегодняшнего дня, обновляется раз в минуту. Подпись «сейчас» по-русски (на макете «now» — ошибка).
- Напоминание: пастельный прямоугольник с левой полосой 3px тёмного оттенка, название + время.
- Модалка: Название, Дата, Время, Тип (цвет из легенды), «Уведомить» (переключатель).
- Мобильный: мини-календарь сверху (свернуть до недели), таймлайн ниже.
- Убрать «+ Добавить календарь» с макета — в MVP не нужно.

### Фаза 8 — Демо-данные, полировка, PWA
- `seed.ts`: при первом запуске заполнить данными с макетов (5 целей, распорядок, 5 напоминаний на сегодня, 10 привычек с частичной историей). В настройках/внизу сайдбара — пункт «Очистить демо-данные».
- Микроанимации: чекбокс (scale 0.9 → 1), появление модалки (fade + translateY 8px), прогресс-бар (transition width 300ms). Уважать `prefers-reduced-motion`.
- Доступность: фокус-кольца (`outline 2px --accent`), `aria-label` у иконок-кнопок, Esc закрывает модалки, все действия доступны с клавиатуры.
- Горячие клавиши: `N` — новая цель/элемент на текущей странице.
- **PWA:** `vite-plugin-pwa` — `manifest` (name «Планер», `theme_color #F7F6F3`, `display: standalone`, иконки 192/512 — простой монохромный знак), офлайн-кэш, `apple-touch-icon`, `viewport-fit=cover`.
- **Уведомления:** в MVP — запрос разрешения + показ `Notification` для напоминаний с `notify: true`, пока приложение открыто. Фоновые push — отложить до бэкенда (зафиксировать в SPEC).

## 5. Правила для исполнителя (Gemini)

1. Перед каждым экраном **открыть соответствующий скриншот** из `design/` и сверять отступы и иерархию.
2. Весь видимый текст — **на русском**. Никакого lorem ipsum, английских подписей и эмодзи.
3. Компоненты страниц **не обращаются к localStorage напрямую** — только через сторы → репозитории.
4. Никаких новых цветов вне токенов. Никаких UI-библиотек (MUI, shadcn и т.п.) — свой минимальный кит.
5. Делать фазы **по порядку**; после каждой фазы — `npm run build` без ошибок TS и проверка в браузере.
6. Не реализовывать бэклог из SPEC (стрики, лента, друзья, ИИ) — только то, что в этом плане.
7. Обновлять `SPEC.md` при любых новых решениях.

## 7. Зафиксированные решения

1. **«Задачи»** — в MVP не делаем (задачи на сегодня = цели периода «День», они сразу отображаются на экране «Обзор»).
2. **Имя пользователя** — при первом запуске (если имя ещё не сохранено) показывается минималистичное окно приветствия: *«Как к тебе обращаться?»* (с плейсхолдером «Абдували»). Сохраняется в профиле.
3. **Распорядок** — по дефолту работает как **повторяющийся шаблон недели («Идеальная неделя»)**. Человек задаёт свой регулярный ритм (работа, тренировки, сон) один раз, а точечные разовые события создаются в «Календаре».
